# data-collection

为通用的页面 judge 造偏好数据:把真实网站的一节换成模型按同样内容重新设计的一节,两版在同一个页面里先后截图,成对作为 (原版, 生成版)。

## 流程

每个网站一个进程(`scripts/site.mjs <url> <dir>`),从头到尾只打开一次页面,所有步骤都在这一个页面里做:

1. 加载页面(`browser.mjs`,见下一节),加载完关掉页面自己的脚本。之后页面静止不动。
2. 读页面(`read-page.mjs`):分节,每节的内容和背景层,设计 token。截整页图 `page.png`,这就是原版。
3. 选 `COUNT` 节(`generate.mjs` 的 `choose`),给每节准备模型要看的东西(`looks/<i>.json`)。
4. 每一节各自走下去,互不等待:请模型设计(`generate.mjs`)→ 换进页面截图(`swap.mjs`)→ 拼成一对、检查(`images.mjs`)→ 没过检查就把问题和渲染图给模型重写,最多 `ROUNDS` 轮。页面同一时间只换一节。

产出(都在 `<dir>/` 下):

| 文件 | 内容 |
|---|---|
| `page.png` | 加载完的整页截图,原版 |
| `sections.json` | 网址、设计 token、每节的位置和内容、内联 SVG 转成的独立文件 |
| `looks/<i>.json` | 给模型看的周围页面截图和每张图的样子 |
| `gen/<i>.html`、`gen/<i>.json` | 生成的片段;对话、模型、每轮用时和用量 |
| `render/<i>.png`、`render/<i>.json` | 换进生成版后这一节框内的截图;伸出多少、内容检查 |
| `pairs/<i>-orig.png`、`<i>-gen.png`、`<i>-side.png`、`<i>-gen.jpg` | 一对图(这一节和上下各 300px 页面)、并排图、给模型重写时看的半尺寸图 |
| `pairs/report.json` | 每对的检查结果,`failed` 为空的才可用 |

`node scripts/run.mjs <out-root> <url>...`(或 `--list <文件>`,一行一个 URL)同时跑多个网站,每个网站一个目录 `<out-root>/<host>/`,日志在 `<out-root>/<host>.log`,同时带着网站名打印到终端。

- `JOBS`(默认 20):同时处理的网站数。每个网站开着一个浏览器和它的页面,约半 GB 内存。一节的请求遇到 429、5xx、断线或超过 `REQUEST_SECONDS`(默认 900)没回,会隔 10s、30s、60s 重试。
- `BROWSER_JOBS`(默认 2):同时加载页面的网站数。加载吃 CPU:没有显卡,页面的动画和 WebGL 都靠 CPU 画,一个重的页面就要占两核左右;4 个同时加载会把 4 核机器压满。加载完脚本关掉的页面在等模型时几乎不占 CPU,不占这个名额。
- `COUNT`(默认 2):每个网站换几节。
- `ROUNDS`(默认 2):没过检查时最多让模型改几轮。
- `LOAD_SECONDS`(默认 300):加载页面的时间上限,超过就放弃这个网站。有的页面太重(比如没有显卡时用 CPU 画的大 WebGL 场景),不为它等。

为什么一次打开做到底:以前录制一次、再回放几次(生成前一次,生成后一次,每轮重写各一次),每个网站要加载五次页面,而且回放出来的页面必须和录制时逐像素一样才能用。页面里只要有随网络先后变化的东西(统计脚本多调了几次随机数,评价墙就换了一种排法;瀑布流按图片到达的顺序排),那一节就和录制时不一样,只能扔掉。现在原版图、给模型的素材、换节后的截图都出自同一个页面,天然一致,不再有"复现不出来";页面也只加载一次。

## 页面怎么跑

`scripts/browser.mjs`。页面加载时带着自己的脚本跑;加载完就把页面的脚本关掉(`Emulation.setScriptExecutionDisabled`),之后页面是一个固定的渲染状态,量尺寸、截图、换节都在这个状态上做。

为什么要关:页面开着脚本,就会对我们的测量和截图起反应。整页截图会临时改窗口大小,页面的 resize、`ResizeObserver`、`IntersectionObserver` 回调随之触发,布局跟着变(cal 的第一节在相邻两次截图之间 796 和 1030 来回跳),每次截出来都不一样。关掉脚本后,页面里除了我们自己改的东西,什么都不会变;静止的页面也不占 CPU。

加载的过程对每个页面都一样:

- 页面时间从它的第一行脚本起就是停住的(Playwright 的 `page.clock`),只由我们按固定步长往前推,每步之后等网络静下来(400ms 内没有请求开始或结束;开了 5 秒以上的请求算长连接,不等)。页面时间停着,页面自己的定时器、轮询都不走,网络很快就静下来,不用干等;靠脚本驱动的动画停在固定的页面时间点上。整个加载推进的页面时间是固定的:先 4 秒,滚动时每停一处 250ms,最后再 4 秒。
- `Math.random` 和 `crypto.getRandomValues` 用固定种子。
- `content-visibility` 一律 `visible`:整页截图要的是整页,不是读者滚到的那一屏。懒加载和滚动出现的内容靠把页面完整滚一遍触发(每停一处先等几帧让页面看到进入视口的元素,再推 250ms 页面时间);不去改 `IntersectionObserver` 让每个元素都报"在屏幕上",那样页面上所有动画和 WebGL 场景会同时一直画,没有显卡的机器会被占满(raycast 一页就卡住几分钟)。
- 视口、语言、时区、配色、减弱动效都固定。
- cookie 横幅、聊天窗、弹窗和不在顶部的固定元素藏起来(`display:none`),不从文档里删:页面的框架(比如 React)以后还会去找这些节点,找不到整个页面就崩了。
- 最后把懒加载的图片和 iframe 一律改成立即加载(离视口远的懒加载图片永远不会加载,等它只是空等),等字体和图片到齐(最多 8 秒,没到的写进日志),把 CSS 动画放到结尾(有限的)或第一帧(无限的),视频暂停在第 1 秒(比 2 秒短的放在一半处;第一帧常是淡入前的黑屏),再关脚本。关掉后先整页截一次扔掉:整页截图会让浏览器加载离视口远的懒加载框架和图片,先截一次,之后每次截图都一样。截 `page.png` 后再量一次各节的位置,和读页面时不一样的节不用(脚本关了,不该有)。

分节(`read-page.mjs`)从 `<body>` 往下,穿过只包着一个大块的外壳,到子元素是一块块叠起来的那一层;太高的块再往下分。`display: contents` 的元素没有自己的盒子,它的子元素按它父元素的子元素排版,分节和读内容时也一样穿过去(Framer 把整页内容包在这种元素里,不穿过去整页只剩页脚两节)。

## 两张图只差生成的内容

一对图要让 judge 只能从设计好坏分辨,两版之间除了模型生成的内容,其他都得一样。下面三条是为此定的原则,具体的检查都从它们来:

**1. 原版图和模型拿到的素材是同一个页面。** 原版图(`page.png`)、给模型的文字图片和周围截图、换节后的截图,都出自同一个加载好、脚本已关的页面,所以模型拿到的就是原版图里的样子。

**2. 生成版只换内容,其余全是原版的。** 原版和每个生成版在同一个页面里截:换一节截图,截完换回去。

- 换节时原节留在原处,内容藏起来(`visibility:hidden`,不动布局),背景层留着:这一节自己,和它里面只画背景或边框、自己不带文字、不是图片视频的元素中,铺满整节的(比如几层渐变)和从这一节上边一直到下边的(比如贯穿全页的网格竖线:碰到上下两边的东西会延续到相邻的节,属于页面,不属于这一节的设计),读页面时标成 `data-backdrop`。所以原版有整节色带的,生成版也有同一条色带。
- 生成的片段放进一个 shadow root(两边的 CSS 互不影响),宿主元素放在原节里面,铺满原节的框。它在原节里面,所以继承原节的文字属性,也和原内容一样被裁剪。它画在原内容所在的那一层:原节内容在这一节的层叠上下文里的最高 z-index。页面别处压在这一节上的东西(固定的导航栏、邻节伸过来的图),在两版里都照样压在上面;垫在下面的照样在下面。以前宿主盖在整页最上层,把这些都盖住了,只好把被别处元素压着的节整个排除(cal、vercel、stripe 的首屏都因此出局);放回原层以后就不用排除了。这些元素在给模型的周围截图里看得到,模型知道它们在那。
- 框的大小定死:提示里给出原版的宽和确切的高,宿主元素就是这个大小(它是 grid,片段的外框拉伸填满)。框里的空间怎么分是模型自己的设计;内容伸出框的上下边(包括被裁掉的)就告诉模型重写。高度不能当捷径,下面的页面也不动。
- 背景层不归模型设计:提示里给出它是什么,要求外框不刷底色、不加边框阴影,里面的卡片面板离开框边。否则生成版常给整个框刷一块颜色,框边就出现一条原版没有的缝,judge 光看缝就能分出两版。接缝检查(下表)量的就是这个,有缝就告诉模型重写。
- 生成版的图是原版截图,只把那一节的框换成换节后截下的框内像素:框外就是原版自己的像素,片段画出框外的东西也不会进到图里。

**3. 生成模型知道的,和原设计师一样多。** 生成版要是因为缺信息出错(白色 logo 放上白卡片、颜色用得和页面习惯不一样、用了页面没加载的字重),judge 学到的就是"有这种错的是生成版",而不是设计的好坏。所以模型拿到原设计师有的一切,只差这一节原来的设计:

- 内容:文字、图片、插图、图标,按阅读顺序;视频和 canvas 截成图。
- 周围页面的截图(`looks/<i>.json` 的 `slot`):这一节上下各 700px 的页面,半尺寸,这一节的内容藏掉、背景层留着,框用虚线标出。页面的风格、配色习惯和这一节的底都看得到,原版的设计看不到。
- 每张图片、插图、图标在页面上的样子(`items`),从原版截图里裁出来:白色 logo 一看就是白的。
- 设计 token:字体、页面实际加载了的字重(只有这些能用)、字号体系(其他各节的文字按角色用的字体、字号、行高、字重、字距和用量;只在这一节出现的样式不给,那是它自己的设计)、颜色、内容宽度、上下两节的背景,和背景层是什么。不给字号体系,生成版的字号字重自成一套,和页面其他部分对不上,这本身又成了认出生成版的捷径。
- 重写时(没过检查)逐条告诉它哪里不对,还给它看它这一版渲染出来的样子(`pairs/<i>-gen.jpg`)。只为这些不涉及审美的问题重写(放不进框、有缝、文字或图片缺了或变了、超出左右、用了页面没加载的字体),不让它反复打磨审美:改到和原版一样好,"原版更好"这个标签就不可靠了。

拿不到原版的 HTML 和布局,两版的差别只在设计上。

## 检查

| 检查 | 在哪 | 含义 |
|---|---|---|
| 内容 | `missingText` / `missingImages` / `brokenImages` | 每段文字、每张图都要出现,图要加载成功;被原版截断的文字只看开头 |
| 放进框 | `spill`(`render/<i>.json` 里还有 `fits`) | 内容伸出框上下边多少像素(包括被裁掉的),0 才算放进去 |
| 接缝 | `seam` | 框的每条边上,紧贴框外和紧贴框内的两排像素有多少不一样,减去原版在同一处本来就不一样的(原版贴边的卡片不算缝);任一边超过 2% 算有缝。页面最边上的那一侧不量 |
| 破版 | `overflow` / `fontsMissing` | 超出框左右的元素数、没加载上的字体 |

都在 `pairs/report.json` 里;每对的 `failed` 列出没过的检查(`fit`、`seam`、`text`、`images`、`overflow`、`fonts`),空的才可用。

## 依赖

- `npm install`(playwright-core)
- Google Chrome:Playwright 自带的 Chromium 不含 H.264/AAC 解码器,放不了大多数网站的 MP4 视频。默认路径 `/opt/chrome-stable/opt/google/chrome/chrome`,别处的用 `CHROME` 指定。安装(不需要 apt 的依赖):
  ```sh
  curl -LO https://dl.google.com/linux/direct/google-chrome-stable_current_amd64.deb
  dpkg -x google-chrome-stable_current_amd64.deb /opt/chrome-stable
  ```
- 模型的地址和 key 来自 `~/.config/ui-rl/judge.env`(`JUDGE_URL`、`DEEPSEEK_API_KEY`)。生成模型由 `GEN_MODELS` 给出(逗号分隔，默认 `deepseek-v4.1-flash,glm-5.3-flash`,都要能看图):每个网站选中的节轮流交给它们，起点随网站变，免得 judge 只学会认一个模型的风格;重写回到同一个模型的同一段对话。
