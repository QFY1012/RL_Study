# data-collection

为通用的页面 judge 造偏好数据:把真实网站的一节换成模型按同样内容重新设计的一节,两版在同一个页面里先后截图,成对作为 (原版, 生成版)。

## 流程

每个网站一个进程(`scripts/site.mjs <url> <dir>`),从头到尾只打开一次页面,所有步骤都在这一个页面里做:

1. 加载页面(`browser.mjs`,见下一节),加载完关掉页面自己的脚本。之后页面静止不动。
2. 读页面(`read-page.mjs`):分节,每节的内容和背景层,设计 token。把每一节藏一次再显示,一轮轮做到页面不再变(见"页面怎么跑"最后一条),截整页图 `page.png`,这就是原版。
3. 选 `COUNT` 节(`generate.mjs` 的 `choose`),量出每节的框(见"两张图只差生成的内容"),给每节准备模型要看的东西(`looks/<i>.json`)。
4. 每一节各自走下去,互不等待:请模型设计(`generate.mjs`)→ 换进页面截图(`swap.mjs`)→ 拼成一对、检查(`images.mjs`)→ 没过检查就把问题和渲染图给模型重写,最多 `ROUNDS` 轮。页面同一时间只换一节。

产出(都在 `<dir>/` 下):

| 文件 | 内容 |
|---|---|
| `page.png` | 加载完的整页截图,原版 |
| `sections.json` | 网址、设计 token(含页面的内容栏 `column`)、每节的位置、内容和内容左右跨到哪(`edges`;选中的节:`box` 是量出的框,`own` 是节元素自己的盒子)、单独存的图(`assets`:内联 SVG、data: URL,和从页面上单独截下的图:视频、canvas、画出来的图、单独渲染不对的 SVG;没选中的节里要截的图还是 `shot:<k>`,只为选中的节截) |
| `looks/<i>.json` | 给模型看的周围页面截图和每张图的样子 |
| `gen/<i>.html`、`gen/<i>.json` | 生成的片段;对话、模型、每轮用时和用量 |
| `render/<i>.png`、`render/<i>.json` | 换进生成版后这一节框内的截图;伸出多少、内容检查 |
| `pairs/<i>-orig.png`、`<i>-gen.png`、`<i>-side.png`、`<i>-gen.jpg` | 一对图(这一节和上下各 300px 页面)、并排图、给模型重写时看的半尺寸图 |
| `pairs/report.json` | 每对的检查结果,`failed` 为空的才可用 |

`node scripts/run.mjs <out-root> <url>...`(或 `--list <文件>`,一行一个 URL)同时跑多个网站,每个网站一个目录 `<out-root>/<host>/`,日志在 `<out-root>/<host>.log`,同时带着网站名打印到终端。

- 流水线:一个网站分两段,加载页面(吃 CPU)和等模型、换节(要等几分钟,几乎不占 CPU,页面脚本已关)。两段流水作业:同时最多 `BROWSER_JOBS`(默认 2)个网站在加载,一个加载完马上开始加载下一个,不管有多少网站在等模型。同时在跑的网站数只受内存限制:每个网站开着一个浏览器和它的页面,约 1GB;可用内存少于 `MEM_RESERVE_MB`(默认 3000)时先不开始新的加载(日志里写 `waiting for memory`)。
- 模型请求遇到 429、5xx、断线或超过 `REQUEST_SECONDS`(默认 900)没回,会隔 10s、30s、60s 重试。
- `COUNT`(默认不限):每个网站换几节;不设就是每个候选节都让模型重写一遍。
- `ROUNDS`(默认 2):没过检查时最多让模型改几轮。
- `LOAD_SECONDS`(默认 300):加载页面的时间上限,超过就放弃这个网站。

为什么一次打开做到底:以前录制一次、再回放几次(生成前一次,生成后一次,每轮重写各一次),每个网站要加载五次页面,而且回放出来的页面必须和录制时逐像素一样才能用。页面里只要有随网络先后变化的东西(统计脚本多调了几次随机数,评价墙就换了一种排法;瀑布流按图片到达的顺序排),那一节就和录制时不一样,只能扔掉。现在原版图、给模型的素材、换节后的截图都出自同一个页面,天然一致,不再有"复现不出来";页面也只加载一次。

## 页面怎么跑

`scripts/browser.mjs`。页面加载时带着自己的脚本跑;加载完就把页面的脚本关掉(`Emulation.setScriptExecutionDisabled`),之后页面是一个固定的渲染状态,量尺寸、截图、换节都在这个状态上做。

为什么要关:页面开着脚本,就会对我们的测量和截图起反应。整页截图会临时改窗口大小,页面的 resize、`ResizeObserver`、`IntersectionObserver` 回调随之触发,布局跟着变(cal 的第一节在相邻两次截图之间 796 和 1030 来回跳),每次截出来都不一样。关掉脚本后,页面里除了我们自己改的东西,什么都不会变;静止的页面也不占 CPU。

加载的过程对每个页面都一样:

- 页面时间从它的第一行脚本起就是停住的(Playwright 的 `page.clock`;装时钟时从 T0 前一小时起,停在 T0:时钟装上就按真实时间走,机器一忙,装好到停下超过 100ms,从 T0 起的时钟就已经过了 T0,停不回去,vercel 因此加载失败),只由我们按固定步长往前推,每步之后等网络静下来(400ms 内没有请求开始或结束;开了 5 秒以上的请求算长连接,不等)。页面时间停着,页面自己的定时器、轮询都不走,网络很快就静下来,不用干等;靠脚本驱动的动画停在固定的页面时间点上。整个加载推进的页面时间是固定的:先 4 秒,滚动时每停一处 1 秒,滚完再 4 秒,藏起杂物后 1 秒,固定 canvas 和视频后 1 秒。
- 脚本开着的时候我们对页面做的每件事(藏起杂物、固定 canvas、截图),之后都再推一段页面时间,让页面把它的反应做完再停住。页面对尺寸变化的反应常常是拖后的:`ResizeObserver` 的回调先节流、500ms 后才用最新的尺寸,而节流的定时器走的是页面时间。整页截图会临时改窗口大小,stripe 的 checkout 示意图在那一刻量到自己只有 5px 宽,按 5/280 缩小;截完尺寸恢复了,可页面时间不再走,恢复的那次更新永远没发出去,示意图就停在 1/56 大,原版图里是空的。
- `Math.random` 和 `crypto.getRandomValues` 用固定种子。
- `content-visibility` 一律 `visible`:整页截图要的是整页,不是读者滚到的那一屏。懒加载和滚动出现的内容靠把页面完整滚一遍触发(每停一处先等几帧让页面看到进入视口的元素,再推 1 秒页面时间)。
- WebGL:没有显卡,WebGL 每一帧都在 CPU 上画,大场景一帧要几秒(raycast 一帧约 2 秒),而页面时间是一秒 60 帧,raycast 加载 300 秒连开头 4 秒都推不完。页面照样逐帧跑(动画库要靠每一帧算到该到的位置),但每帧都在画的上下文(渲染循环)只在每 1 秒页面时间里真画一帧,其余帧的绘制调用跳过;偶尔才画的(内容变了才重画的场景)照常画。加载最后几帧全部照画,每个循环停在它跑到的地方。raycast 现在约 100 秒加载完。
- 页面只在视口里才显示的东西:很多页面用 `IntersectionObserver` 看哪些部分在视口里,不在的就不显示,或者显示成另一个样子(arc 把不在视口里的节调暗到 0.4;raycast 一节的演示只在视口里时才挂载,滚走就卸载)。读者是一节节滚着看的,每节都在视口里;整页截图却只有一个滚动位置(顶部)。所以滚完一遍以后,观察窗口的 `IntersectionObserver` 一律报告"所看的全在视口里",并且一直这样报告;观察别的容器的(轮播的轨道)不动。
- 随滚动位置变的样子(滚动事件、CSS 滚动驱动动画):滚动时每停一处,记下每个元素的样子(透明度、可见性、变换、滤镜、裁剪、颜色、背景色等不影响布局的属性),最后按它最居中的那一站的样子固定下来。
- 视口、语言、时区、配色、减弱动效都固定。
- cookie 横幅、聊天窗、弹窗和不在顶部的固定元素藏起来(`display:none`),不从文档里删:页面的框架(比如 React)以后还会去找这些节点,找不到整个页面就崩了。
- 最后把懒加载的图片和 iframe 一律改成立即加载(离视口远的懒加载图片永远不会加载,等它只是空等),等字体和图片到齐(最多 8 秒,没到的写进日志),把 CSS 动画放到结尾(有限的)或第一帧(无限的),视频暂停在第 1 秒(比 2 秒短的放在一半处;第一帧常是淡入前的黑屏),再关脚本。
- 关脚本不能改变页面的样子,而 HTML 在脚本禁用时有几处渲染不同,都事先固定成开着脚本时的样子:`<noscript>` 藏起来;没有 `controls` 属性的视频不显示原生控件(脚本禁用时浏览器会给视频加控件,一换帧就冒出来);canvas 和视频固定成它们当时的画面(CSS `content`),因为脚本禁用时 canvas 显示的是后备内容(重新排版后变空,只靠宽高属性定尺寸的塌成 0×0;stripe 的数据可视化因此是空的),视频也不能指望停住的那一帧一直显示(arc 有一段视频在截 `page.png` 时是白的,换一次帧才出来)。能读出像素的直接读(canvas 自己的像素;视频等这一帧真正显示后画到 canvas 上),读不出的(画过跨域图片的 canvas、跨域视频)把它单独截下来:其他元素都暂时不可见、背景透明,它自己和祖先的透明度、滤镜、混合、遮罩、变换暂时撤掉,免得固定后再叠一次。单独截只能在关脚本前:脚本一关,canvas 当场就画成空的。`@media (scripting)` 没法改回去,所以关脚本前后比一次所有元素的位置和样子,变了的打上 `data-changed-without-scripts`,含有这种元素的节不用。关掉后先整页截一次扔掉:整页截图会让浏览器加载离视口远的懒加载框架和图片,先截一次,之后每次截图都一样。
- 我们对页面的临时改动(藏起一节的内容、单独截一个元素、按视口里的样子固定)都放在自己的样式表里,用 data 属性选中元素,撤销时去掉属性;不读写页面自己的 `style` 属性:样式属性读出来不一定是设进去的样子(用 CSSOM 把简写设成 `var()` 的,读出来各个长属性是空的),原样写回去就丢了(cal 的按钮因此没了背景)。
- 读完分节后,把每一节藏一次再显示,一轮轮做到一轮下来页面不再变(最多 4 轮;变过就重读一遍分节),然后才截 `page.png`:有的页面要重新计算一次样式才到它自己的不动点(stripe 的导航由一个看自己是否溢出的 CSS 动画决定显示哪些按钮,重算一次就变),后面换节时的藏和显示会触发它,原版图就和换节后的页面对不上了。截 `page.png` 后再量一次各节的位置,和读页面时不一样的节不用(脚本关了,不该有)。

分节(`read-page.mjs`)找的是页面从上到下一层层叠起来的带区。从 `<body>` 往下:一个元素的子元素(在文档流里的)一个在一个下面,没有两个是并排的(竖直方向重叠、横向却基本分开),它就是一摞,每个子元素是一节;太高的(超过 1800px)或只是外壳的(文档流里只有一个子元素)再按同样的办法往下分。子元素并排的(分栏、卡片网格)整个是一节,多高都不拆,拆开就把一个带区切碎了(stripe 的卡片网格原来被切成两张宽卡片两节,其余卡片和标题丢了)。两个子元素竖直重叠但横向占同一片(负 margin 把下一块拉上来压在上一块上)仍算一摞。绝对定位、固定定位的子元素不在这一摞里,压在上面(一节的背景层、浮在页面上的页眉),不算节;但外壳里只有一个子元素、又有内容绝对定位压在它上面的(标题压在一张大图上),两者合起来才是一个带区,不往下分。不到 120px 又什么都没有的(空白、分隔线)不算节。`display: contents` 的元素没有自己的盒子,它的子元素按它父元素的子元素排版,分节和读内容时也一样穿过去(Framer 把整页内容包在这种元素里)。

压在一节上、却不在任何一节里的层,算那一节的(`data-part`)。页面的框架可以把一节的一部分内容放进文档别处的一个层里,再定位到这一节上面(vercel 首屏的集装箱 canvas 和 "READ THE RECAP" 在 `<body>` 末尾的一个固定定位层里):读者看它就是这一节的,不算进来的话,换节时它还压在生成的内容上,模型也不知道它。所以不在任何一节里、绝对或固定定位的最外层元素,里面有看得见的东西(文字、图),它显示的东西至少一半压在哪一节上,就是哪一节的:和这一节一起读内容、一起藏。没有一半压在同一节上的(横跨页面顶部的导航栏)还是页面的。

## 两张图只差生成的内容

一对图要让 judge 只能从设计好坏分辨,两版之间除了模型生成的内容,其他都得一样。下面三条是为此定的原则,具体的检查都从它们来:

**1. 原版图和模型拿到的素材是同一个页面。** 原版图(`page.png`)、给模型的文字图片和周围截图、换节后的截图,都出自同一个加载好、脚本已关的页面,所以模型拿到的就是原版图里的样子。

**2. 生成版只换内容,其余全是原版的。** 原版和每个生成版在同一个页面里截:换一节截图,截完换回去。

- 换节时原节留在原处,内容藏起来(`visibility:hidden`,不动布局,不带过渡),它的层(`data-part`)整个藏起来,背景层留着:这一节自己,和它里面只画背景或边框、自己不带文字、不是图片视频的元素中,铺满整节的(比如几层渐变)和从这一节上边一直到下边的(比如贯穿全页的网格竖线:碰到上下两边的东西会延续到相邻的节,属于页面,不属于这一节的设计),读页面时标成 `data-backdrop`。所以原版有整节色带的,生成版也有同一条色带。
- 框是这一节的内容露出来的地方,或新内容放进来能露出来的地方。内容可以画到节元素外面(行高比字号小的标题、伸出右边的轮播、阴影),节元素的一部分也可以被压住(下一节拉上来盖住了它的底部)。生成版的图框外是原版自己的像素,所以框外不能有原版这一节的任何东西,框里也不能有看不见的地方。量法:在这一节周围截一条整页宽的带,依次截原样的、藏起内容的、再在节元素自己的盒子上放一个和生成版宿主同层、涂满品红的探针的;藏起内容后有任何变化的像素是原内容露出的地方,放上探针后明显变化(某个通道超过 32)的像素是新内容能露出的地方,两者的外接框就是框。三张都按同一条带截:带的截图和整页截图在同一处不一定一样(framer 的毛玻璃面板两种截法差几个色阶,拿带去比 `page.png`,框就被撑大 275px,生成的内容压到了下一节的标题上);探针只算明显的变化,别处的毛玻璃透过来的一点品红不算。带从上下各 400px 起,变化碰到带的边就加倍。框里出现了别的节的内容(原版就压在邻节上),这一节怎么生成都会和邻节重叠,不用:逐个藏起附近(1500px 内)的其他节,框里有像素变了就是。所有候选节都先量框、查重叠,再从剩下的里面挑。以前框就是节元素的盒子,伸出去的原内容(stripe 卡片轮播伸出右边的半张卡、arc 每节压在框线上的标题)藏了以后,框外还是原版像素,留在了生成版图里。
- 生成的片段放进一个 shadow root(两边的 CSS 互不影响),宿主元素放在原节里面,铺满这一节的框。它在原节里面,所以继承原节的文字属性,也和原内容一样被裁剪。它画在原内容所在的那一层:原节内容在这一节的层叠上下文里的最高 z-index。页面别处压在这一节上的东西(固定的导航栏、邻节伸过来的图),在两版里都照样压在上面;垫在下面的照样在下面。以前宿主盖在整页最上层,把这些都盖住了,只好把被别处元素压着的节整个排除(cal、vercel、stripe 的首屏都因此出局);放回原层以后就不用排除了。这些元素在给模型的周围截图里看得到,模型知道它们在那。
- 框的大小定死:提示里给出原版的宽和确切的高,宿主元素就是这个大小(它是 grid,片段的外框拉伸填满)。框里的空间怎么分是模型自己的设计;内容伸出框的上下边(包括被裁掉的)就告诉模型重写。高度不能当捷径,下面的页面也不动。
- 背景层不归模型设计:提示里给出它是什么,要求外框不刷底色、不加边框阴影,里面的卡片面板离开框边。否则生成版常给整个框刷一块颜色,框边就出现一条原版没有的缝,judge 光看缝就能分出两版。接缝检查(下表)量的就是这个,有缝就告诉模型重写。
- 生成版的图是原版截图,只把那一节的框换成换节后截下的框内像素:框外就是原版自己的像素,片段画出框外的东西也不会进到图里。

**3. 生成模型知道的,和原设计师一样多。** 生成版要是因为缺信息出错(白色 logo 放上白卡片、颜色用得和页面习惯不一样、用了页面没加载的字重),judge 学到的就是"有这种错的是生成版",而不是设计的好坏。所以模型拿到原设计师有的一切,只差这一节原来的设计:

- 内容:文字、图片、插图、图标,按阅读顺序;只显示一张背景图、里面什么都没有的元素也是图片(用背景图做的 logo,framer 的客户 logo 墙原来一个都没读到)。
- 画出来的图是一张图,不拆成文字:页面标成一张图的(`role="img"`),或不给读屏软件、文字在页面别处又读不到的(`aria-hidden`,不是同一个标题给读屏的完整版之外的那份可见副本,也不是轮播重复的卡片):用 HTML 搭的产品界面、示意图、键盘。它里面的标签是图的一部分,不是这一节的文案;拆成一条条文字交给模型,模型只能凭标签重搭一个界面(stripe 的界面示意图一节 163 条文字,现在是 8 张图)。只看页面自己的无障碍标注,所以对任何网站都一样;没标注的示意图(cal 的日历、stripe 连接图的下半部分)还是文字,见 `PLAN.md`。
- 每张给模型的图都和它在页面上显示的一样。视频、canvas、画出来的图,从页面上单独截下来(其他元素暂时不可见、背景透明;祖先的透明度、滤镜、混合、遮罩撤掉,那是这一节怎么用它,不是它本身),PNG。内联 SVG 存成它自己的源码,也单独截一张,两者比一比:单独当图片用的 SVG 没有页面在旁边,页面的 CSS、字体、图片都用不上,渲染出来可能完全不同(raycast 的键盘是 SVG 里套的一段 HTML,靠页面的 CSS 排成键盘,单独渲染就塌成一列 F1–F12 的标签,模型看到的是键盘,用上的是这一列),不一样(超过 1% 的像素差 32 以上)就给截图。单独截下来什么都看不见的图(全透明:叠在一起交替淡入的两个 logo 里藏着的那个,被容器裁掉的)不算内容。截图是整页截图,只为选中的节截。
- 周围页面的截图(`looks/<i>.json` 的 `slot`):这一节上下各 700px 的页面,半尺寸,这一节的内容藏掉、背景层留着,框用虚线标出。页面的风格、配色习惯和这一节的底都看得到,原版的设计看不到。
- 每张图片、插图、图标在页面上的样子(`items`),从原版截图里裁出来:白色 logo 一看就是白的。
- 设计 token:字体、页面实际加载了的字重(只有这些能用)、字号体系、颜色、上下两节的背景,和背景层是什么。字号体系是其他各节的文字用的字体、字号、行高、字重、字距:先列各节的标题(每节最大的字)和正文(每节字数最多的)用的是哪一种、在哪几节,再列全部样式和用量;只在这一节出现的样式不给,那是它自己的设计。不给字号体系,生成版的字号字重自成一套,和页面其他部分对不上,这本身又成了认出生成版的捷径。
- 网格:框在页面上的横向位置(页面坐标和框内坐标都给)、页面的内容栏(多数节的内容从哪条左边线开始,右边线对称;`tokens.column`),上下两节的内容左右跨到哪。只给一张半尺寸截图时,模型不知道邻节的文字从哪条线开始,生成版的文字往里缩进 26px,和上下两节对不齐(stripe #12),一眼就能认出来。
- 重写时(没过检查)逐条告诉它哪里不对,还给它看它这一版渲染出来的样子(`pairs/<i>-gen.jpg`)。只为这些不涉及审美的问题重写(放不进框、有缝、文字或图片缺了或变了、超出左右、用了页面没加载的字体、原版对齐页面网格而生成版没有),不让它反复打磨审美:改到和原版一样好,"原版更好"这个标签就不可靠了。

拿不到原版的 HTML 和布局,两版的差别只在设计上。

## 检查

| 检查 | 在哪 | 含义 |
|---|---|---|
| 内容 | `missingText` / `missingImages` / `brokenImages` | 每段文字、每张图都要出现,图要加载成功;被原版截断的文字只看开头 |
| 放进框 | `spill`(`render/<i>.json` 里还有 `fits`) | 内容伸出框上下边多少像素(包括被裁掉的),0 才算放进去 |
| 接缝 | `seam` | 框的每条边上,紧贴框外和紧贴框内的两排像素有多少不一样,减去原版在同一处本来就不一样的(原版贴边的卡片不算缝);任一边超过 2% 算有缝。页面最边上的那一侧不量 |
| 破版 | `overflow` / `fontsMissing` | 超出框左右的元素数、没加载上的字体。截图和检查之前先排一次版:字重要等用它的文字排版时才开始加载,不排版就既不等它,截图里还是替代字体,检查也误报(arc 同一个片段第一轮报 `fonts`、第二轮通过) |
| 网格 | `offGrid`(`edges` 是生成版的内容左右跨到哪) | 内容(全部,或只看文字)从页面内容栏的左边线开始(差 2px 以内)、从页面边上开始,或在页面上居中(差 3px 以内),算对齐网格。原版对齐而生成版不对齐的,和邻节对不齐,单凭这一点就能认出来。原版自己就不对齐的不查 |

都在 `pairs/report.json` 里;每对的 `failed` 列出没过的检查(`fit`、`seam`、`text`、`images`、`overflow`、`fonts`、`grid`),空的才可用。

## 网站名单

要的是设计好看的网站，所以名单从设计收录站来，不用流量排行。

1. Mobbin 的网站库(Sites,496 个，每个带网址):登录后从它的列表接口 `api/discover/fetch-discover-page-sites` 一页页取(每页 24 个，每页间隔 4 秒)。账号不写进仓库。
   Awwwards 拒绝云端机器的连接(连接被对方重置),在自己的电脑上取:`node scripts/awwwards.mjs <out-dir>`(要 `npm install` 和 Google Chrome)。它在屏幕上开一个 Chrome,逐页翻 Sites of the Day 和全部网站的列表，再打开每个条目页取 "Visit" 链接:列表一次一页，条目页同时开 `JOBS`(默认 4)个标签页，每个标签页翻下一页前停 `PAUSE_MS`(默认 1500)。Awwwards 问"你是不是人"时在窗口里回答，脚本会等。中断后再运行从断处接着取。交回的是 `<out-dir>/awwwards.txt`。
2. `node scripts/galleries.mjs <out-dir> [收录站]...`:从收录站的站点地图读出每个条目页，取出条目页上指向被收录网站的链接。现在有 Minimal Gallery(约 3000 条)、SaaS Landing Page(约 850 条)。CSS Nectar 试过，收的网站大多不好看，不用。新的先取(老的更可能已经关站)。每个收录站同时 `JOBS`(默认 5)个请求，每个之后停 `PAUSE_MS`(默认 300)。已取过的条目不重取。
3. `node scripts/domains.mjs <out> --list <来源>=<文件>... [--tranco <top-1m.csv>]`:合并、去重、逐个访问首页，只留下返回 200 的英文 HTML 首页(有标题，不是停放页、验证墙、错误页、登录页、成人或博彩站)。一个品牌只留一个(google.com 和 google.co.uk 算一个;跳转到别的域名的算那个域名;framer.website 这类谁都能开站的托管域名按完整主机名算)。名单里的网址一律取它的首页。凑够 `TARGET`(默认 4500)个就停。产出 `<out>.tsv`(来源、排名、域名、网址、语言、标题)、`<out>.rejected.tsv`(没收的和原因)、`<out>.txt`(给 `run.mjs --list` 用)。

都要 `NODE_USE_ENV_PROXY=1`。名单是数据，不进 git,放在 `/home/user/ui-rl-scratch/domains/`。

## 不给风格的生成(2026-10-18)

想知道模型自己做决定时会做成什么样:不给页面的样式信息,看它写出来的东西。三个实验,都是 2026-10-18 跑的,各用 8 个网站。一节的实验用 monotonomo、duties、focalglow、useportal、nelsoncash、gonefishing、theworkshop、imprint;整个首页的两个实验用 monotonomo、duties、standard-projects、useportal、nelsoncash、canvas、gonefishing、imprint。

| 实验 | 怎么跑 | 结果 |
|---|---|---|
| 一节,简单提示词 | `GEN_PROMPT=plain node scripts/run.mjs ...`(中转 deepseek-v4.1-flash):只给框的大小和内容项,不给页面字号、配色、网格和截图;图片照给。只按 `fit`、`text`、`images`、`overflow` 打回重写(`REVISED`) | 51 节里只有 14 节通过检查,失败的多是 `seam`:模型给自己画背景,和上下两节接不上。样子是典型的 AI 风格(衬线大标题、卡片、渐变),单看还行,放进原页面就不合群。「合不合页面」比「好不好看」客观 |
| 整个首页,只给描述 | `node scripts/plain-site.mjs <out> --list <名单>`:只给域名、`<title>` 和 meta description | 中转端点和官方 deepseek-flash 都写得很像样,而且风格统一(米色底、斜体衬线强调、等宽小标签、深色按钮)。内容是模型自己编的 |
| 整个首页,给全部真实文字 | `node scripts/plain-site.mjs <out> --text <v18 的运行目录> --list <名单>`:再给真实首页的每一条文字(按阅读顺序,来自 `sections.json`),要求一字不改、不加自己的字 | 官方 deepseek-flash 照样像样。用上的文字条数:monotonomo 53/57、duties 83/83、standard-projects 123/123、useportal 84/87、nelsoncash 54/54、canvas 116/116、gonefishing 65/66、imprint 67/69。只有图片多的 nelsoncash 排成了一张清单 |

结论:「内容是模型自己编的才好看」这个猜测被第三个实验否定了。模型在网站上的审美来自对落地页这种结构的熟悉,不来自自由发挥。同一个模型写没见过结构的报告就难看(见 `ui-rl/README.md`「只给数据让模型写报告」)。所以网站数据收集建议暂停,待定(见 `PLAN.md` 第 9 条)。

数据(共约 195MB)只在跑实验的容器里,没有上传到 Drive(Drive 的工具只能内联上传,传不了这么多文件),容器回收后就没了:
- `/home/user/ui-rl-scratch/data-collection/v19-plain/`(一节的实验)
- `site-plain/`(只给描述,中转端点)
- `site-brief/`(只给描述,官方 flash)
- `site-text/`(给全部文字,官方 flash)
- `site-plain/compare/` 是真网站和生成版并排;`site-text/compare/` 是真网站、只给描述、给全部文字三张并排

名单就是上面的网站(首页网址),要的话按表里的命令重跑。
